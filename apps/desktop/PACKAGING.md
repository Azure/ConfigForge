# ConfigForge — Packaging

> Installers for Windows (NSIS + portable zip) and Linux
> (AppImage / deb / rpm / tar.gz). **All builds are unsigned** (no
> code-signing credentials in CI); the trust path is building from
> source, with optional local self-signing via
> `scripts/generate-dev-cert.ps1`. Auto-update is documented in
> [`UPDATING.md`](./UPDATING.md). The macOS author
> flavor lives on the `mac-author-build` branch and uses its own
> `electron-builder.author.yml`.
>
> **Current through v0.3.92:** the release pipeline generates a
> CycloneDX SBOM per platform, enforces
> `npm audit --omit=dev --audit-level=high` as a release gate,
> pins `electron-builder` invocation via `npx --no-install`, and
> tilde-pins `electron` + `electron-builder` in `package.json`
> (CF-SEC-011 / 012 / 014). See [`CHANGELOG.md`](../../CHANGELOG.md).

## Quick start

From the repo root:

```powershell
# Windows installer (NSIS) + portable zip — 5–8 minutes cold,
# 30 seconds when Electron is cached.
npm run desktop:dist:win

# Linux tarball — works from any host (no Linux native tools needed).
# AppImage / deb / rpm are configured but require a Linux build host
# (see "Cross-platform build matrix" below).
npm run desktop:dist:linux

# Both at once (Linux tar.gz only when run from Windows):
npm run desktop:dist
```

Artifacts land in `apps/desktop/release/<version>/`. The directory
is gitignored.

## What gets produced

After `npm run desktop:dist:win` from a Windows host:

| File | Format | Size | Use case |
|---|---|---|---|
| `ConfigForge-Setup-${version}-x64.exe` | NSIS installer | ~113 MB | End-user install (Start menu shortcut, Add/Remove Programs entry, optional desktop shortcut) |
| `ConfigForge-Setup-${version}-x64.zip` | Portable zip | ~149 MB | Unzip-and-run, no install. Useful for sandbox testing or restricted environments. |
| `ConfigForge-Setup-${version}-x64.exe.blockmap` | Block map | ~120 KB | electron-updater delta updates |

After `npm run desktop:dist:linux` (or from Linux host):

| File | Format | Size | Use case |
|---|---|---|---|
| `configforge-${version}-x64.tar.gz` | Tarball | ~140 MB | Universal portable Linux. Unpack, `chmod +x configforge`, run. |
| `configforge-${version}-x86_64.AppImage` | AppImage | ~140 MB ⚠️ Linux host only | Self-contained universal Linux binary. Most user-friendly. |
| `configforge_${version}_amd64.deb` | Debian | ~100 MB ⚠️ Linux host only | Debian/Ubuntu native install. |
| `configforge-${version}.x86_64.rpm` | RPM | ~100 MB ⚠️ Linux host only | Fedora/RHEL/openSUSE native install. |

## Cross-platform build matrix

| Build host | Win NSIS | Win zip | Linux tar.gz | Linux AppImage | Linux deb | Linux rpm | macOS .dmg |
|---|---|---|---|---|---|---|---|
| **Windows** | ✅ | ✅ | ✅ | ❌ needs `mksquashfs` | ❌ needs `dpkg-deb` | ❌ needs `rpmbuild` | ❌ |
| **Linux** (CI ubuntu-latest) | ⚠️ needs wine | ⚠️ needs wine | ✅ | ✅ | ✅ | ✅ | ❌ |
| **macOS** | ⚠️ needs wine | ⚠️ needs wine | ✅ | ✅ | ✅ | ✅ | ✅ — only from `mac-author-build` branch via `electron-builder.author.yml` |

**Why the gaps:**
- Windows can't natively produce AppImage / deb / rpm because
  those formats require Linux-native tools (`mksquashfs` for
  AppImage; `fakeroot` + `dpkg-deb` for deb; `rpmbuild` for rpm).
  These run on Linux but not on Windows even via WSL → Windows
  filesystem boundary issues.
- The release CI matrix uses `ubuntu-latest` for Linux artifacts
  and `windows-latest` for Windows artifacts — each runner builds
  natively and uploads to a unified release.
- macOS .dmg can only be built on macOS, and it's intentionally
  scoped to the `mac-author-build` branch — that branch's
  `electron-builder.author.yml` ships an author-only flavor with
  a distinct appId and no device-operation capabilities.

**Workaround on Windows (development only):**
- Build inside WSL Ubuntu: `wsl npm run desktop:dist:linux`. Slower
  due to filesystem boundary; tested but not scripted into the
  workflow.
- Or use Docker: `electronuserland/builder` image, mount the repo,
  run electron-builder inside the container. Requires Docker
  Desktop.

## Pre-build checklist

`apps/desktop/electron-builder.yml` controls every aspect of the
build. Before running `npm run desktop:dist`, verify:

- [ ] `node scripts/verify-public-package-assets.mjs` passes from the
      repository root. The `dist`, `dist:win`, and `dist:linux` scripts run
      this guard automatically before `electron-builder`.
- [ ] `apps/desktop/build/icon.ico` exists (regenerated by
      `npm run icons` from `docs/theme/favicon.svg`)
- [ ] `apps/desktop/build/icon.png` exists
- [ ] `apps/desktop/dist/` has a fresh build (the `dist:*` scripts
      run `build` first; manual builds can stale)
- [ ] If running on Windows, the lockfile is intact — see the
      npm bug #4828 caveat in [UPDATING.md](./UPDATING.md). Use
      `npm ci` rather than `npm install` to keep
      `package-lock.json` byte-for-byte stable.
- [ ] The `oscfg` binary is **not** present under
      `apps/desktop/resources/oscfg/<platform>-x64/` if you intend
      to ship the resulting installer to anyone other than yourself
      — v0.2.0+ deliberately omits the CLI from installers.
      `resources/oscfg/` is a dev-only convenience drop and is not
      referenced by `electron-builder.yml`.

## Post-build smoke checklist

After `npm run desktop:dist:win`:

1. **Launch test** — double-click
   `release/<version>/win-unpacked/ConfigForge.exe` (or run
   the NSIS installer first then launch the installed copy):
   - [ ] Window opens within 3 seconds
   - [ ] Mica titlebar visible on Win11 22000+
   - [ ] Sidebar shows all seven nav items in order: Dashboard, My Baselines,
         Microsoft Baselines, Export Readiness, Diff, Benchmark Mapping,
         Settings
   - [ ] Clicking each nav item routes correctly

2. **IPC bridge** — open DevTools (F12) → Console:
   - [ ] No red errors
   - [ ] `await window.cfs.platform.info()` returns
         `{platform: 'win32', isWindows11: true|false, …}`

3. **Install/uninstall round-trip** — run NSIS installer:
   - [ ] Installer chooses default install dir
   - [ ] Start menu entry created
   - [ ] Desktop shortcut created (if requested)
   - [ ] Add/Remove Programs lists "ConfigForge"
   - [ ] Uninstaller removes all files cleanly

4. **Resource files** — after install, verify:
   - [ ] `<install-dir>\resources\public-assets\_baselines\` exists
         with sample baselines
   - [ ] No CIS XCCDF, OVAL, catalog, or derived baseline file appears under
         `public-assets`. In particular,
         `public-assets\_baselines\cis\_data\` must not be packaged.
   - [ ] **No `oscfg-resources/` directory** under
         `<install-dir>\resources\` — v0.2.0+ ships **no** CLI
         binary. `scripts/verify-no-cli-binary.sh` enforces this
         at release time. Users install `oscfg` separately per
         [INSTALL.md](https://github.com/Azure/ConfigForge/blob/main/INSTALL.md).

5. **SBOM artifact (release builds only)** — when triggered via
   the release workflow, verify the per-platform SBOM is staged
   alongside the installers:
   - [ ] `apps/desktop/release/sbom-windows-latest.cdx.json`
         exists and is non-empty
   - [ ] File contains a `"components"` array (the workflow's
         smoke check fails the job otherwise)
   - [ ] Uploaded to the GitHub Release draft alongside
         `SHA256SUMS-windows.txt`

After Linux tarball / AppImage / deb / rpm:

1. **Extract test** — on a Linux host:
   ```bash
   VERSION=''
   [[ "$VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+$ ]] || {
     echo 'Set VERSION to X.Y.Z before continuing.'
     exit 1
   }
   tar -xzf "configforge-${VERSION}-x64.tar.gz"
   cd "configforge-${VERSION}-x64"
   chmod +x configforge
   ./configforge
   ```
   - [ ] Window opens
   - [ ] Sidebar nav works
   - [ ] No console errors in terminal

2. **SBOM artifact (release builds only)**:
   - [ ] `apps/desktop/release/sbom-ubuntu-latest.cdx.json`
         exists and is non-empty
   - [ ] Uploaded to the GitHub Release draft alongside
         `SHA256SUMS-linux.txt`

## Troubleshooting

**Build hangs on `executing @electron/rebuild`** — first run
downloads Electron prebuilds (~100 MB per target platform).
Subsequent runs hit the cache at
`%LOCALAPPDATA%\electron-builder\Cache\` (Windows) or
`~/.cache/electron-builder/` (Linux/macOS).

**`mksquashfs` / `dpkg-deb` / `rpmbuild` not found** — you're
trying to build a Linux installer on Windows. Use `tar.gz` only,
or move to a Linux host (CI / WSL / Docker).

**SmartScreen blocks the unsigned installer** — expected; builds are
unsigned. Choose *More info → Run anyway*, build from source, or
optionally self-sign your own local build with
`scripts/generate-dev-cert.ps1`.

**`mksquashfs: invalid file size`** — symptom of building on a
filesystem that doesn't support large files (FAT32 or older
exFAT). Build target a real NTFS / ext4 / APFS volume.
